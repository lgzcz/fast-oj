## 已知限制与后续

| 事项 | 现状 |
|------|------|
| 语言 | C / C++ / Python（见 [Python 提交](python.md#python-提交护栏装在解释器里边界还是牢房)）。Python 的时限原样算、内存下限 32MB（64MB 的题照常收）、只在牢房开着的判机上收；`pypy` 之类的加速解释器没有，Java/Go 等仍未做 |
| 判题方式 | SPJ 判题器、交互题与文件 IO 已做（见[判题方式](judging.md#判题方式普通比较--spj-判题器--交互题)），并由判机自报能力把关派单：没自报 `checker`/`interactor`/`options`/`file_io` 的机器领不到对应工单。仍**没有**：一条"这些题现在没人能判"的显式提示——队列里的提交只会显示「等待判题」，要去看 `/judges` 才知道是哪台机器掉队；判题器只能用判机有的工具链（`c`/`cpp`/`python`）；多条用例同时失败时只留**第一条**的评语；交互器读不到选手的转写文件（那是对话结束后才写的，对话本身走 stdin/stdout） |
| 判机隔离 | Linux 上每次运行都有命名空间牢房（无网络、看不到宿主目录、内核 rlimit 兜 CPU/内存/进程数）+ 一层 seccomp **黑名单**（`socket` 全家、`ptrace`/`process_vm_*`、`mount`/`unshare`/`setns`/`bpf`/`kexec` 等一律 EPERM，见[系统调用过滤](judge-isolation.md#系统调用过滤seccomp-黑名单)），root 与非 root 两种部署都能开；容器再套一层。仍**没有**：系统调用**白名单**（实测装不下 g++ 与 CPython，且要能编译就必须放行 `execve`/`clone3`/`wait4`，所以牢房里仍能起子进程）、pid 命名空间（需要 jailer 多 fork 一层，代价是退出码要自己传回来、内存轮询读的是 jailer 的 RSS，见[判题沙盒](judge-isolation.md#判题沙盒-internaljail一次运行一个牢房)）、Windows 上的任何文件/网络隔离（平台没有这套机制，`-sandbox=on` 会直接拒绝启动） |
| 账号 | 注册可关；**邮箱验证已做**（`/admin/site` 的第六个开关 + 图形化 SMTP 配置 + 发送测试邮件），未验证的账号能读能登录，但不能提交代码与参加比赛，验证链接一次有效、可在设置页重发。**忘记密码已做**：`/forgot` 寄 30 分钟一次性的重置链接，令牌绑签发时的密码指纹，改成功后旧密码与全部会话失效。仍**没有**：改邮箱入口（改了就得由管理员重发验证，因为旧邮箱收到的那条链接会被拒绝）、把验证做成"没验证连登录都不行"的更严模式 |
| 工单 | 已做（五类、四状态、私密、流水、处理人角标、附件上传；见[附件](attachments.md)）。仍**没有**：新工单的邮件/推送提醒、按人分派与 SLA |
| 比赛 | 已做（限时、加入码私有、队伍、OI/IOI/ACM 三种赛制独立榜、封榜）。OI 比赛中不出榜。仍**没有**：虚拟排名（参赛者不插进别人的榜）、比赛中改时限或换数据后对历史提交的**自动/批量**重算（一条一条重判已经有了，见[重判](judge-isolation.md#重判旧提交不会因为判机升级自己改判)；一场比赛几十条时得手动按，按下去还会插到队首）、队长踢人/转让队长的完整 UI、比赛内单独的时限配置（用题目自己的时限）；时间全站按服务器时区，没有用户时区 |
| 升级 0015 | 老比赛里 `mode='oi'` 的**算法口径变了**（0013 那版算的其实是 IOI 的最高分）。数据不迁移：表结构只是多认一个 `'ioi'`，历史 `oi` 比赛从这次起按「最后一次提交、同分同名次、赛中不出榜」算，主办方要复核老比赛的赛制选择 |
| 比赛封榜 | 结束**不自动放榜**，要主办方手动勾「榜单公示」——忘了关是泄题，多一次点击不会 |
| 统计 | 排行榜只有「按去重 AC 题数」，无难度、标签、通过率排序 |
| 安全与审计 | 已做（0027 `audit` 只追加表 + `/admin/audit`，`ip.manage` 可看）：**特权动作**入库——授予/撤销能力、改角色、封号与解禁、注销、封与解 IP、站点设置保存、判题器存取、删用例与清空、删题、删比赛、移下题目、重新判题（写明重判之前的状态与判定）、工单改状态与删除，判机协议那一路的**被拒鉴权**与**领单/回报**，以及**权限确认失败**（`step_up.denied`：拿着能改权限的会话却连着五次答不出密码，见[身份再确认](permissions.md#改权限之前的身份再确认2-分钟)）。仍**只有 stderr** 的：提交与建题/改题的普通写路径、登录与注册、封禁**命中**的每一条被拒请求（一条一行会变成攻击者可控的写放大，只看内存流量表）、删帖删评论删动态这类用户自己的内容操作。审计表**没有**保留期与归档：只追加意味着它会一直长，真要长期跑还得配轮转 |
| 防作弊 | 无代码查重。登录/注册/发动态/提交/建题都有速率限制（见[参数](flags.md#参数)：提交与建题按人算，`-submit-per-minute` 默认 10），比赛内的提交同样计入；注册到第二个号、登录错到第 3 次起要等完人机验证那几秒**并且真的点一下那个格子**（点法是一次 `POST /verify`，服务端只在时间走完且请求像浏览器时盖章，见[人机验证窗](operations.md#人机验证窗观感是演给人看的等待是强制的)）。没有的是"同一份代码换个变量名再交"的查重 |
| 附件与图片 | 题面不能贴图（外链可以），无附件上传 |
| 静态资源 | 已按内容哈希加 `immutable` 一年缓存；模板与样式仍内嵌在二进制里，改样式要重新编译并重启 |
